# UI Evidence: Prepared-study library and journey player

## Status

Proposed

## Owners

Unassigned. Issue #14 names JC as the build owner; no design approval is recorded.

## Affected Surfaces

- `#/research/studies`: study library with design-group and topic filters,
  progress and resume. Linked from the learn page's
  "More practice" row as "Browse prepared studies" (it replaces the three-paper
  activities link; `#/research/activities` still opens directly).
- `#/research/studies/<slug>`: intro, one challenge per screen, optional bonus
  offer and final paper reveal.

## Problem and Constraints

Issue #14 asks for a Duolingo-style player that serves every prepared study with
one set of components. This is a browser-only frontend preview, like the reasoning
preview: answers are checked against authored keys in the tab and progress lives
in `localStorage`. The server-assessed path arrives when uploaded papers (#12)
share this player. The existing learning rules hold: answers hidden until Check,
results only from results-stage challenges, paper identity hidden until the final
reveal, one retry then an explanation, and points once per solved challenge. No
lives, streaks, leaderboards or shops.

Every study is listed, reviewed or not. A `reviewed: false` study says on its
reveal that it is not content-reviewed yet.

## Direction

Lesson data reuses the pipeline's `Lesson` and `Challenge` shapes
(`apps/web/src/research/studies/types.ts`). Each study is a card in `cards.ts`
(slug, teaser, question, design group, topic, minutes, `reviewed` and required
challenge ids) plus a lesson body in `data/<slug>.ts`. The library and the reveal's
next-study suggestion read cards only; a body loads when its study opens, so each
body is its own build chunk. Card order is display order: non-school topics first,
design groups interleaved. Topics are the seven groups in
`docs/research/PAPER_SCREENING.md` "Topic coverage", one illustration each.

Lessons for stored papers without an authored study are generated by Nemotron
(`scripts/generate-prepared-studies.ts`, record in
`docs/research/GENERATED_STUDIES.md`). They pass the same checks as authored ones
(`scripts/prepared-study-checks.ts`) and stay `reviewed: false`. Every scene kind
is part of the shared contract in `packages/contracts/src/scenes.ts`, so prepared
studies, generated lessons and uploaded papers use the same schemas, gates and
renderers. Each challenge adds an optional `responseStyle`: `cards`, `pills`
(short answers) or `tap` (answer by tapping a diagram element). Besides the four
original kinds (see [SCENE_AUTHORING.md](../SCENE_AUTHORING.md)):

| Kind          | Prepared studies (design group)                                                  | What it shows                                                                           |
| ------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `timeline`    | basketball-maths (classroom), sleep-school (longitudinal)                        | Waves on one axis; reported n as bars so attrition is visible                           |
| `association` | breakfast-grades (correlational), dog-ownership-among-seniors (longitudinal)     | Reported r, β or OR on a gauge; derived r² grid after Check                             |
| `estimate`    | learning-styles (null), sleep-school (longitudinal)                              | Reported intervals against a reference value, optional predict-then-reveal              |
| `tests`       | remembering-doctor-appointments (between), stroop-task-performance (replication) | A family of reported p-values on a log axis against α; derived chance check after Check |
| `units`       | bus-ridership-behavior (classroom), breakfast-grades (correlational)             | Nested assigned, sampled, measured and analysed counts; derived ratio after Check       |
| `matrix`      | vaccine-misinformation-correction (between), phone-use-while-driving (within)    | Conditions side by side; same/differs markers after Check show what else changed        |

The added scenes in generated lessons attach to existing challenges and cite
existing verbatim evidence; questions, answers and excerpts are unchanged. Where a
scene cites an excerpt the challenge did not list, that id was added to `refs`.

## Uploaded papers

Uploaded papers (#12) now share this player at `#/research/play/<sessionId>`.
`JourneyPlayer` takes an optional `driver`. Without one, prepared studies keep
the browser store and authored keys exactly as before. With one, the saved
learning session checks every answer and owns every transition, and the player
keeps only the unchecked draft (`client-state.ts`, version-bound, per tab).
`studies/uploaded.ts` maps the public session to `PreparedStudy` and
`StudyProgress`. Challenges the server has not sent yet are placeholders that
are never rendered, because the server releases one challenge at a time. Sending
the whole lesson would let the browser read results-stage scenes and evidence
before the design decisions.

Small seams in this player's components, all optional with the previous defaults:
`JourneyChrome` `closeHref`/`closeLabel`, `StudyIntro` `backHref`/`backLabel`/`busy`,
`StudyReveal` `extra`/`actions`, `PreparedStudy.kicker` (replaces the design-group
label), and `Burst` moved to `studies/Burst.tsx` so preparation can reuse it.
The driver's `renderExtra` adds the written-reasoning field and the AI coach
(`ReasoningCoach.tsx`) for uploads only. Card fields for an upload (teaser,
question, minutes, decorative group and topic, reveal takeaway) are derived on
the server by `apps/api/src/research/study-card.ts`, which hides the paper's title
and authors. See [HANDOFF_UPLOAD_JOURNEY.md](../HANDOFF_UPLOAD_JOURNEY.md) for
the decisions waiting on review.

## Micro-interaction inventory

Timings reuse `sceneTiming` and the shared `SceneMotion` provider. Reduced motion
comes from the operating system or the saved app setting and settles in place.

| Code | Trigger                                   | Response                                                                                                       | Reduced motion                      |
| ---- | ----------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| P1   | Press a choice, pill or tap step          | Native checked state at once; 0.985 press scale; key badge swaps to a check (160 ms)                           | State only, no scale or swap motion |
| P2   | Number keys 1–6, Enter                    | Select the option; Enter checks or continues when focus is not on a button or link                             | Same                                |
| P3   | Check with nothing selected               | Button stays disabled; dock note says what to do                                                               | Same                                |
| P4   | Check, correct                            | Dock tints blue, feedback springs up 14 px, +10 points tag, points chip pops, focus moves to feedback          | Instant tint and text, focus moves  |
| P5   | Check, first miss                         | Dock tints soft amber, misconception plus hint, chosen option marked amber. No red, no shake                   | Instant                             |
| P6   | Try again                                 | First answer stays marked "First try"; hint repeats above the choices; focus to question                       | Instant                             |
| P7   | Second miss                               | Neutral slate dock with the explanation; best answer tagged; mascot "caring"                                   | Instant, mascot static              |
| P8   | Double click on Check                     | The second click within 280 ms cannot trigger Continue, so feedback is never skipped                           | Same                                |
| P9   | Reveal covered results                    | Cover leaves, intervals grow from their point estimate (300 ms), focus to the figure                           | Figure appears settled              |
| P10  | Evidence unlocks after Check              | Resolution card, comparison difference and r² grid enter (160 ms); withdrawn content is removed without exit   | Appear settled                      |
| P11  | Continue                                  | Progress bar springs to the new share with a single glint; next question enters (220 ms); focus to its heading | Bar jumps, no glint                 |
| P12  | First results or interpretation challenge | "Results unlocked" or "Time to interpret" cue pops in once                                                     | Static cue                          |
| P13  | Finish the study                          | One burst of rings and sparks behind the celebrating mascot; stat tiles and paper card follow                  | No burst, settled content           |
| P14  | Filter the library                        | Active chip pill slides between chips; cards reflow with layout springs; leaving cards are inert               | Instant filter                      |
| P15  | Hover a library card                      | Lift 3 px and art motif scales 3%, fine pointers only                                                          | None                                |

Mascot reactions are limited to the intro, the first first-try solve, a second miss
and completion. Restored progress, refresh and back navigation never replay
entrances: the shared provider only allows entrances after it has mounted.

## Required States

- Library: filtered empty with clear filters, resume card for the most recent study in progress. Saved progress
  for a slug with no card (a removed paper) is ignored.
- Player: loading, intro, answering, retry feedback, retrying, solved, explained,
  bonus offer, reveal. An unknown slug shows a recovery screen.
- Scenes that fail validation fall back to plain choices.
